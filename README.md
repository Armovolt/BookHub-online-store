## Огляд проєкту

BookHub - це веб-додаток онлайн книжкового магазину з повноцінним RESTful API. Застосунок реалізує повний цикл роботи електронної комерції: перегляд каталогу книг, додавання до кошика, оформлення замовлень, система відгуків та адмін-панель для управління контентом.

**Основні функції:**
- 🔐 Система авторизації користувачів (адміністратор/користувач)
- 📚 Каталог книг з пошуком та фільтрацією
- 🛒 Кошик покупок з сесійним зберіганням
- 📝 Система відгуків з модерацією
- 🏪 Адмін-панель для управління книгами, замовленнями та відгуками
- 🔌 RESTful API з повною документацією Swagger

## Архітектура контейнерного рішення

### Docker образ
- **Базовий образ:** `python:3.11-slim`
- **Розмір фінального образу:** ~250MB (можна перевірити командою `docker images`)
- **Використання багатоетапної збірки:** ✅ Так
  - Перший етап: `python:3.11-slim` як builder для встановлення залежностей
  - Другий етап: чистий `python:3.11-slim` для фінального образу
- **Оптимізація:** Використання віртуального середовища Python та кешування шарів

### Docker Compose
- **Кількість сервісів:** 1 (веб-додаток BookHub)
- **Використовувані volumes:**
  - `bookhub_data` - для збереження SQLite бази даних
- **Мережа:** Автоматично створена мережа для комунікації
- **Health check:** Інтегрована перевірка здоров'я кожні 30 секунд

## Прийняті рішення та обґрунтування

### Вибір базового образу
**Обрано `python:3.11-slim` замість `python:3.11-alpine` через:**
1. **Сумісність:** Alpine використовує musl libc, що може викликати проблеми з деякими Python пакетами
2. **Стабільність:** Slim базується на Debian, що забезпечує кращу сумісність
3. **Розмір:** Різниця в розмірі незначна (~50MB), але стабільність важливіша для продакшену
4. **Простота:** Не потрібно встановлювати додаткові системні пакети для компіляції

### Організація збереження даних
**SQLite база даних зберігається через Docker volumes:**
1. **Volume `bookhub_data`** монтується до `/app/data` у контейнері
2. **Шлях до БД:** `/app/data/bookhub.db` (конфігурований через змінну середовища `DATABASE_PATH`)
3. **Створення директорії:** Автоматичне створення при першому запуску
4. **Права доступу:** Додаток запускається під непривілейованим користувачем `appuser` (UID 1000)

**Переваги такого підходу:**
- ✅ Дані зберігаються між перезапусками контейнера
- ✅ Можливість створення backup через `docker cp`
- ✅ Автоматичне управління правами доступу
- ✅ Легка міграція на іншу систему

### Оптимізації
1. **Багатоетапна збірка:**
   - Перший етап: встановлення залежностей та компіляція
   - Другий етап: чистий образ з готовими пакетами
   - Результат: зменшення розміру фінального образу

2. **Кешування залежностей:**
   - `requirements.txt` копіюється окремо для кешування шарів Docker
   - Зміни в коді не викликають перевстановлення залежностей

3. **Безпечний запуск:**
   - Використання непривілейованого користувача `appuser`
   - Встановлення правильних прав на директорії

4. **Health check:**
   - Автоматична перевірка доступності додатку
   - Перевірка підключення до бази даних
   - Інтервал: 30 секунд, timeout: 3 секунди

5. **Мінімальний образ:**
   - Видалення тимчасових файлів після встановлення пакетів
   - Використання `.dockerignore` для виключення непотрібних файлів

### 🚀 Швидкий старт

#### Крок 1: Клонування репозиторію
```bash
# Клонувати репозиторій (або завантажити архів)
git clone https://github.com/Armovolt/BookHub-online-store.git
cd BookHub-online-store
```

#### Крок 2: Підготовка конфігурації
```bash
# Створити конфігураційний файл з шаблону
cp .env.example .env

# Опціонально: відредагувати .env за потребою
# Редагувати SECRET_KEY, порт тощо
```

#### Крок 3: Збірка та запуск
```bash
# Зібрати Docker образ
docker-compose build

# Запустити контейнер у фоні
docker-compose up -d
```

### Крок 4: Перевірка статусу
```bash
# Перевірити статус контейнера
docker-compose ps

# Переглянути логи
docker-compose logs -f web

# Перевірити health check
curl http://localhost:5000/health
```

### 🛠 Корисні команди Docker
```bash
# Зупинити контейнер
docker-compose down

# Зупинити та видалити дані (базу)
docker-compose down -v

# Перезапустити контейнер
docker-compose restart web

# Виконати команду в контейнері
docker-compose exec web sh

# Створити backup бази даних
docker-compose exec web cp /app/data/bookhub.db /app/data/backup.db

# Копіювати базу на хост
docker cp bookhub_app:/app/data/bookhub.db ./backup.db

# Перевірити розмір образу
docker images | findstr "lab3-4-flask-webapp"
```


### 🔧 Розробка та налагодження
**Development режим**
Для розробки можна використовувати змінену версію docker-compose.override.yml:
```yaml
version: '3.8'
services:
  web:
    environment:
      - FLASK_ENV=development
    volumes:
      - .:/app  # Монтування коду для hot reload
```

**Перевірка логів**
```bash
# Всі логи
docker-compose logs web

# Логи в реальному часі
docker-compose logs -f web

# Фільтрація помилок
docker-compose logs web | findstr "ERROR"
```
